# FD AI Desktop 0.2.7 Usability Release

## Goal

Ship a focused desktop release that makes the employee workflow obvious and reliable: a prominent
new-task action, stable sidebar navigation, native image understanding, cancellable Feishu setup,
a draggable Windows titlebar, and concise Agent progress instead of raw operational narration.

## Architecture

Reuse the existing owners. `SidebarChrome` and `Sidebar` own navigation layout; `ChatHeader` owns
the title hit target inside the Electron drag region; `CodexAdapter` maps persisted attachments to
Codex App Server inputs; `MessagesTimeline.logic` owns timeline folding; `FeishuConnector` owns the
local CLI authorization state machine. No new runtime, provider, connector, or persistence owner is
introduced.

## Tech Stack

Electron, React, TypeScript, Effect, Codex App Server v2 protocol, Vitest/Vite Plus, electron-builder.

## Change Necessity

Configuration cannot correct a title button covering the drag region, a data URL sent where the
App Server supports a local image path, the active-turn folding rule, or connector cancellation.
The minimum change boundary is the existing UI, Codex adapter, and Feishu owners listed below.
Decision: code-change.

## Existence And Architecture Integrity

- Reuse `SidebarChromeHeader`, `SidebarChromeFooter`, `ChatHeader`, `deriveTurnFolds`,
  `CodexAdapter.resolveAttachment`, and `FeishuConnector`.
- Do not add a second attachment pipeline, custom image parser, alternate connector runtime, or
  parallel activity store.
- The canonical persisted attachment remains the source of truth; Codex receives `localImage`.
- Detailed Agent events remain stored and expandable; only the default projection is summarized.
- Decision: reuse-existing.

## Complexity Budget

- `Sidebar.tsx` and `MessagesTimeline.tsx` are large, so changes there stay wiring/presentation only.
- Stateful logic belongs in `MessagesTimeline.logic.ts`; connector state remains in
  `FeishuConnector.ts`; image conversion remains in `CodexAdapter.ts`.
- New responsibility is not added to `ChatView.tsx` or orchestration.
- Budget result: within-budget with focused helpers and regression tests.

## Delivered Behavior

- The primary sidebar now keeps tasks and workspaces separate, uses a full-width new-task action,
  keeps Connectors below it, and places Usage, Settings, and Sign out at the bottom.
- Settled tasks no longer render on the primary sidebar. Settings now owns a dedicated
  **Settled tasks** route that lists settled threads and restores them to the active list.
- Settled-task classification continues to use the existing T3 owner and respects server
  capabilities, pinned tasks, snoozed tasks, automatic age, explicit settlement, and merged or
  closed change requests.
- The workspace picker now sits in the composer footer immediately after FD Skills. Draft tasks no
  longer show a second workspace action above the composer.
- Active Agent work shows elapsed time and up to four recent Chinese action summaries while
  preserving expandable raw commands and tool details. Settled work folds to elapsed time plus the
  final action summary.
- Settings, workspace import/clone flows, source control, appearance, theme import/editing, and the
  adjacent accessibility labels are localized for employee use.
- On Electron desktop, the lower-left account control shows `displayName` and falls back to
  `username`; its menu routes to usage, settings, and sign out. Web keeps the existing separate
  sidebar entries so this desktop projection does not change browser behavior.
