# Desktop 0.2.28 Candidate

Status: published and active.

Packaged 0.2.27 testing against the production gateway reproduced a file preview
failure. An ordinary V4 Flash task created its HTML output in the default office
workspace even though T3 had allocated a separate task project. The preview
correctly rejected that file as outside the task root.

The FD driver now preserves an explicitly selected project, task directory or
worktree in every runtime mode. Default office sessions keep their existing
permission profile. T3 asset containment checks remain in place.

Focused regression coverage verifies project, task and worktree execution paths
under all four permission modes, plus default office session behavior.

Previously generated files are not automatically moved between workspaces.

## Acceptance Limits

This verifies synthetic task persistence and HTML preview, not recovery of an
affected user's old conversations. A complete Windows installer upgrade cycle
and interactive macOS upgrade remain untested. General CI jobs using the
unavailable Blacksmith runner remained queued; the explicit source and context
checks above ran on available GitHub-hosted runners.

Workspace switching coverage is not comprehensive: the current composer fix
carries text when creating a new draft, but reused draft branches and attachment
transfer still need follow-up. Do not describe all workspace switching cases as
fixed by this release.
