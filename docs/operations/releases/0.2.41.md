# 0.2.41：附件不再“超过本轮容量”，长 PDF 文字优先、按需看图

本版本解决员工反复遇到的“附件与问题的总文本超过本轮容量，请拆分后重试”，重做 PDF 附件的读取方式（先读文字，图表和扫描页按需查看），修复网络短暂波动时被退出登录，并吸收上游 t3code 一批稳定性修复。Electron 从 41.5 升级到 44.7。

## 附件不再“超过本轮容量”

0.2.40 及以前，这个报错非常容易出现，原因有三：

- 附件文字的上限按“16 万字符”计，总检查却按“20 万字节”计；一个汉字占 3 字节，超过约 6.6 万字的中文附件必然失败。
- Word 文档的每个段落被重复读取两次，表格单元格三次以上，同样的内容占用加倍。两者叠加，约 3.3 万字的中文合同就会失败。
- Excel、长 PDF 没有按需读取的途径，只能整份放入。

本版本：

- 统一按字节分配，修复 Word 段落和表格重复读取。
- 每轮放入对话的仍是约 20 万字节（约占模型上下文的四分之一），但超出部分不再丢失或报错，而是留给 AI 按需读取：PDF 按页、表格按行或用完整 CSV 计算、Word / PPT / 文本 / 粘贴内容按行或关键词（新工具“读取文档内容”）。
- 一次发多个附件时，粘贴内容、图片识别结果和各文件文字按比例分配本轮篇幅；估算不足时依次压缩可以事后再读的部分，不再整轮失败。只有直接输入在输入框里的文字本身超过约 20 万字节时，才会提示改为附件发送。

## PDF：文字优先，按需看图

- 上传 PDF 后先提取全部页面的文字，文字页不再逐页“看图”，几秒内即可开始回答；最多读取 500 页。
- 每页自动判断是文字页、含图表页还是扫描页。扫描页发送前识别（最多 40 页，每次 3 页并发，失败自动重试）；含图表的页在问题涉及图中数值时由 AI 调用“查看 PDF 页面”按需查看。
- 文字特别多的 PDF 先放入前面的页面和其余页面的目录，AI 需要时调用“读取 PDF 页面”按页继续读取（每次最多 20 页），不会因为太长而报错。
- 能看图的模型（DeepSeek V4.1 Flash、Qwen 3.8、Kimi K3）查看页面时直接拿到页面图片；DeepSeek V4 Pro、GLM 5.2 使用授权的 Flash 视觉预处理，问到某个具体读数时把该页分成上下两半放大后再识别（同样耗时，读数明显更准）。
- 读图表时先按图例确认系列颜色、说明所用坐标轴，避免把另一条线的峰值当成所问的系列。
- 修复：开启推理的请求经阿里云返回的推理条目带 `status: null`（Kimi K3 还带 `content: null`），桌面端误判为“图片识别服务返回了不完整或不兼容的响应”。0.2.40 中 Kimi K3 识别扫描版 PDF 和文档内图片因此全部失败，只能由模型自己再看一遍页面。
- AI 只通过上述工具读取附件，不再在电脑上搜索 PDF 或用脚本裁剪附件。
- 时间线上显示“查看 PDF 页面”“读取 PDF 页面”。

## 大表格

- 修复：几个上万行的 Excel 一起发送时整轮失败，提示“附件与问题的总文本超过本轮容量，请拆分后重试”。
- 每个工作表最多读取 20 万行，完整数据另存为 CSV；对话中按附件公平分配篇幅，按整行截断并注明放入了多少行。
- 统计、分组、去重等全表计算由 AI 读取完整 CSV 计算；需要看具体行时调用“读取表格行”（每次最多 500 行）。

## 登录

- 修复：网络短暂不可用（网关 503、断网）时定期检查把员工退出登录。登录凭据仍有效时保持登录，网络恢复后继续使用；启动时的检查仍然严格。

## 上游同步

- SQLite 改用 synchronous=NORMAL，不再每条事件都刷盘；磁盘慢或被杀毒软件扫描时不再卡住、显示“重新连接中”（t3code #19205）。
- 附件和项目中的 SVG 以禁止脚本的沙箱方式提供，其中的脚本不能再以本地服务的身份运行（#5916）。
- Windows 下拒绝含换行或引号、会被命令行包装脚本重新解析的编辑器路径（#17749）。
- macOS 上“粘贴为纯文本”不再重复粘贴（#11958）。
- 退出时最多等待本地服务 5 秒（#7599）。
- 桌面端管道按 socket 读取，服务能及时退出（#17386；同样修复 FD 凭据管道）。
- 上下文用量接近一百万时显示“1m”而不是“1000k”（#17539）。
- Electron 41.5.0 → 44.7.0（剪贴板改用 Promise API）。

## 注意

- Electron 44 要求 macOS 13 或更高版本。
- macOS 系统通知需要签名标识与 bundle ID 一致；安装包的 ad-hoc 签名应当满足，需在 Mac 真机上确认通知能弹出。
- 企业 Skill 对话中出现的视图 `v_customer_fp_bind_info_manager` 查询报错属于企业数据库 / 网关一侧，与桌面端本次修改无关，单独排查。
