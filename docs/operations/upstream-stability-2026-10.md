## Flash 长任务：已确认的证据

2026-10-15 对线上受影响账号核对了模型消费记录、工具审计和容器日志：

- 10:45:49、11:10:10、11:17:28，上游渠道 18 返回 HTTP 429 / `Too many requests`。
- 12:26:52，同一账号又收到 HTTP 429 / `Allocated quota exceeded`。
- 这些 HTTP 错误未出现在所查询的消费记录中；仅凭消费记录的 `type=2` 不能判断整个任务成功。
- 技能工具查询中出现过 `query_not_allowed` 和单次 `query_timed_out`，但不能据此把所有长任务失败归因于工具超时。
- 本分支 `FdEnterpriseEventPolicy` 将所有结束错误变成同一句英文，掩盖了实际原因。

现改为固定的中文分类提示：限流、额度不足、上下文超限、超时、连接中断及未知失败。原始错误不进入持久化事件，避免错误正文中携带企业数据。先添加回归测试，旧实现 7 个失败；修改后该文件 11 个测试通过。

本分支打包 Codex CLI 0.159.3。该版本 `model-provider-info/src/lib.rs` 的 `to_api_provider` 固定 `retry_429: false`，因此增加 `request_max_retries` 不能解决限流。网关 [PR #121](https://github.com/hezhaoqian1/FD-gateway/pull/121) 增加最多两次的瞬时限流重试，尊重 Retry-After、输出边界与取消；不重试配额不足，不重放整个任务或工具。

此处已确认的是该账号发生过上述上游拒绝。尚未取得用户机器上对应 toast 的原始运行时事件，因此不能把每一次报错都归为同一原因。
