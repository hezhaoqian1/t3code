# FD AI native HarmonyOS client

This application is a native ArkUI client. It does not load the T3 web renderer
or use ArkWeb for the main surface.

The client talks to the FD Runtime over HTTPS and an authenticated, resumable
SSE turn stream. An optional WebSocket replay stream is enabled only when the
gateway advertises that capability. The default endpoint is the production
gateway, but debug builds can point at a staging runtime in
`entry/src/main/ets/config/HarmonyConfig.ets`.

Build with DevEco Studio, or from a project where DevEco has generated the
`hvigorw` wrapper:

```text
hvigorw assembleHap --mode module -p product=default
```

The repository does not vendor the Harmony SDK or the DevEco-generated wrapper.
The package build script checks for that wrapper and reports the missing
tooling clearly; run it on a machine with DevEco Studio and the compatible
HarmonyOS SDK installed. The wrapper is intentionally not committed because it
is generated by the installed DevEco toolchain.

When a signed-in session is restarted without a network connection, the app
shows the last visible workspace snapshot from Harmony Preferences while it
tries to refresh the T3 thread catalog. The snapshot contains thread shells,
visible messages, the local send queue, and safe attachment metadata. It does
not contain passwords, provider keys, runtime credentials, local file URIs,
short-lived preview URLs, tool parameters, reasoning overlays, or resume
cursors. Uploads and attachment processing that were interrupted by a restart
are shown as needing the file to be selected again. A successful remote refresh
replaces the cached projection with the server-backed thread and history.
